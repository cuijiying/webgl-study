06 · 二维矩阵 —— 用一个矩阵统一所有变换

把平移、旋转、缩放、投影组合成单个 3×3 矩阵，并掌握 WGSL 中 mat3x3 的内存对齐。

一、为什么要用矩阵？

前几节里，每加一个变换就要在着色器里多写几行，而且顺序极易出错。矩阵的妙处在于：任意多个变换可以预先相乘成一个矩阵，着色器里只做一次矩阵 × 向量。

二维变换用 3×3 矩阵表示（把二维点扩展为 (x, y, 1) 的齐次坐标），这样平移也能用矩阵乘法表达。

二、三种基本矩阵

$$ T=\begin{bmatrix}1&0&t_x\\0&1&t_y\\0&0&1\end{bmatrix}\; R=\begin{bmatrix}\cos&-\sin&0\\\sin&\cos&0\\0&0&1\end{bmatrix}\; S=\begin{bmatrix}s_x&0&0\\0&s_y&0\\0&0&1\end{bmatrix} $$

另外还有一个投影矩阵，负责把像素坐标变换到裁剪空间（含 Y 翻转）：

projection(w, h) = [ 2/w, 0,    0,
                     0,  -2/h,  0,
                    -1,   1,    1 ]  // 列主序

三、相乘顺序决定一切

let mat = m3.projection(w, h);
mat = m3.multiply(mat, m3.translation(tx, ty));
mat = m3.multiply(mat, m3.rotation(rad));
mat = m3.multiply(mat, m3.scaling(sx, sy));

🧮读法：最右边的矩阵最先作用于顶点。上面等价于：顶点 → 缩放 → 旋转 → 平移 → 投影 → 屏幕。这正是我们想要的「先缩放/旋转、后平移」的自然顺序。

⚠️矩阵乘法不满足交换律：T·R ≠ R·T。交换平移和旋转会得到完全不同的结果。试着在代码里交换两行，观察 F 的运动轨迹变化。

四、WGSL mat3x3 的内存陷阱（核心知识点）

这是 WebGPU 新手最常踩的坑。WGSL 的 mat3x3f 由 3 个列向量 vec3 构成，而每个 vec3 在内存里对齐到 16 字节（占 12 字节数据 + 4 字节填充）。所以一个 mat3x3 在 uniform 缓冲里实际占用 48 字节，而不是 9×4=36 字节。

列float 索引字节偏移
第 0 列 (m0,m1,m2)0,1,2 + pad0
第 1 列 (m3,m4,m5)4,5,6 + pad16
第 2 列 (m6,m7,m8)8,9,10 + pad32
// 把 9 元素矩阵填进 12 元素数组（每列后留 1 个空位）
padded[0]=mat[0]; padded[1]=mat[1]; padded[2]=mat[2];
padded[4]=mat[3]; padded[5]=mat[4]; padded[6]=mat[5];
padded[8]=mat[6]; padded[9]=mat[7]; padded[10]=mat[8];

💡相比之下 mat4x4f 没有这个烦恼——它由 4 个 vec4 组成，本身就是 16 字节对齐，64 字节连续，可以直接 writeBuffer。所以从第 07 节起的 3D 部分我们一律用 mat4x4，省心很多。

五、动手练习

  1. 交换 translation 与 rotation 两行的相乘顺序，观察差异。
  2. 添加一个「绕鼠标点旋转」的效果：先平移到鼠标位置、旋转、再平移回来。
  3. 把矩阵改成 mat3x3 直接存 36 字节（不对齐），观察渲染错乱——加深对对齐的理解。
