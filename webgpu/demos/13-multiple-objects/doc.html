13 · 绘制多个物体 —— 动态 Uniform 偏移

用一个大缓冲 + dynamic offset 高效绘制成百上千个物体。

一、为什么需要它？

在第 9 节（相机）里，我们为环上的每个 F 都建了独立的 uniform buffer 和 bind group。物体一多，这种做法就会有问题：

  • 创建大量 GPU 对象，浪费显存和初始化时间；
  • 每帧若要更新它们，要发很多次 writeBuffer；
  • 切换 bind group 本身也有开销。

WebGPU 给出的方案是动态偏移 (dynamic offset)：把所有物体的 uniform 数据塞进同一个大 buffer，绘制每个物体前只用一个整数偏移量「跳」到它的数据段。

二、内存布局：256 字节对齐

动态偏移有个硬性规则：偏移量必须是 minUniformBufferOffsetAlignment 的整数倍，默认是 256 字节。所以即使每个物体只需 80 字节（一个 mat4x4f = 64 + 一个 vec4f = 16），我们也要按 256 字节为步长排列：

// 每个物体占 256 字节槽位（其中前 80 字节是真实数据，其余是填充）
物体 0 → 偏移 0
物体 1 → 偏移 256
物体 2 → 偏移 512
物体 i → 偏移 i * 256

📏对齐值可以从 adapter.limits.minUniformBufferOffsetAlignment 读取。大多数设备是 256，少数是 64。写通用代码时应该读取而不是硬编码。

三、声明带动态偏移的 Bind Group Layout

关键点：layout:'auto' 生成的布局 不 支持动态偏移。必须手动创建 layout，并把 hasDynamicOffset 设为 true：

const bgl = device.createBindGroupLayout({
  entries: [{
    binding: 0,
    visibility: GPUShaderStage.VERTEX | GPUShaderStage.FRAGMENT,
    buffer: { type: 'uniform', hasDynamicOffset: true },  // ← 关键
  }],
});
const pipelineLayout = device.createPipelineLayout({ bindGroupLayouts: [bgl] });

然后管线用这个显式 layout，而不是 'auto'：

const pipeline = device.createRenderPipeline({
  layout: pipelineLayout,   // ← 不再是 'auto'
  /* ...vertex / fragment... */
});

四、Bind Group 的 size = 单个物体大小

创建 bind group 时，绑定的 size 不是整个大 buffer，而是单个物体的数据大小（这里 80 字节）。偏移留 0，运行时再传：

const bindGroup = device.createBindGroup({
  layout: bgl,
  entries: [{ binding: 0, resource: {
    buffer: uniformBuffer,
    offset: 0,
    size: 80,   // 一个 mat4x4f(64) + 一个 vec4f(16)
  }}],
});

五、绘制循环：每个物体切换偏移

pass.setPipeline(pipeline);
pass.setVertexBuffer(0, vertexBuffer);
for (let i = 0; i < n; i++) {
  pass.setBindGroup(0, bindGroup, [i * 256]);  // ← 第三参数是动态偏移数组
  pass.draw(vertexCount);
}

同一个 bindGroup 复用了 N 次，只靠偏移数组区分。注意第三个参数是数组——因为一个 bind group 里可以有多个动态资源，要按声明顺序一一对应。

六、一次性写入所有数据

每帧我们把全部物体的矩阵和颜色填进一个大 Float32Array，一次 writeBuffer 全部上传，比逐个上传高效得多：

for (let i = 0; i < n; i++) {
  const mvp = computeMatrix(i);
  const base = i * (256 / 4);   // 以 float 为单位的起始下标
  big.set(mvp, base);            // 0..15: 矩阵
  big[base + 16] = r; big[base + 17] = g; big[base + 18] = b; big[base + 19] = 1; // 颜色
}
device.queue.writeBuffer(uniformBuffer, 0, big, 0, n * (256 / 4));

七、动态偏移 vs 其它方案

方案优点缺点
每物体独立 buffer/bg（第9节）直观简单物体多时浪费、慢
动态偏移（本节）一个 buffer，切换便宜需 256 对齐、手写 layout
Storage Buffer + 实例化最高效，可上万物体需 instance_index、稍复杂

🚀对于真正海量的物体（粒子、草地），更推荐 实例化绘制：pass.draw(vertexCount, instanceCount) 配合 storage buffer，用 @builtin(instance_index) 在着色器里索引每个实例的数据，一次 draw 调用画完所有物体。

八、动手练习

  1. 把物体数量上限从 64 改成 256，观察是否仍流畅。
  2. 给每个物体加上不同的旋转动画（结合下一节）。
  3. 尝试用 adapter.limits.minUniformBufferOffsetAlignment 动态计算 STRIDE。
  4. 改用实例化绘制重写本例，对比代码量与性能。
