01 · Hello Triangle —— 第一个三角形

理解 WebGPU 的最小启动流程与「命令录制 + 批量提交」模型。

一、本节目标

  • 掌握 WebGPU 初始化四件套：adapter → device → context → configure
  • 编写第一个 WGSL 着色器（顶点 + 片元）
  • 理解渲染管线 (Render Pipeline) 的作用
  • 掌握命令编码器、渲染通道、队列提交的工作方式

二、WebGPU vs WebGL 的根本区别

如果你学过 WebGL，第一件要重塑的认知是：WebGL 是「即时模式」，每个 gl.xxx() 调用会立刻影响 GPU 状态；WebGPU 是「录制模式」，你先把所有指令录进一个命令缓冲（Command Buffer），最后一次性提交到 GPU 队列执行。

对比项WebGLWebGPU
编程模型即时、全局状态机命令录制 + 提交
着色器语言GLSLWGSL
状态管理大量 gl.enable/bind打包进 Pipeline / BindGroup
深度范围 (NDC z)-1 ~ 10 ~ 1
异步基本同步初始化大量使用 Promise
计算能力无原生 compute原生 Compute Shader

三、逐步拆解代码

1) 初始化：获取设备并配置画布

if (!navigator.gpu) throw new Error('不支持 WebGPU');
// 适配器 = 一块物理/虚拟 GPU 的抽象
const adapter = await navigator.gpu.requestAdapter();
// 设备 = 与该 GPU 通信的逻辑句柄，创建资源都靠它
const device = await adapter.requestDevice();
const context = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat();
context.configure({ device, format, alphaMode: 'opaque' });

📌adapter / device / context 的关系：

adapter 是「哪块 GPU」；device 是「与它对话的逻辑设备」，所有缓冲区、纹理、管线都由 device 创建；context 是 canvas 的 WebGPU 上下文，负责把渲染结果显示到屏幕。

getPreferredCanvasFormat() 返回当前平台最优的纹理格式（通常是 bgra8unorm），用它配置 canvas 能避免一次额外的格式转换。

2) 编写 WGSL 着色器

@vertex
fn vs(@builtin(vertex_index) i : u32) -> @builtin(position) vec4f {
  let pos = array<vec2f, 3>(
    vec2f( 0.0,  0.5),
    vec2f(-0.5, -0.5),
    vec2f( 0.5, -0.5),
  );
  return vec4f(pos[i], 0.0, 1.0);
}

@fragment
fn fs() -> @location(0) vec4f {
  return vec4f(1.0, 0.43, 0.78, 1.0);
}

WGSL 语法要点：

  • @vertex / @fragment 是着色器阶段属性，标记函数入口。
  • @builtin(vertex_index) 是内置输入，相当于 WebGL 的 gl_VertexID，告诉你当前是第几个顶点（0、1、2）。
  • @builtin(position) 是必须返回的裁剪空间坐标，相当于 gl_Position。
  • @location(0) 表示片元着色器输出写到第 0 个颜色附件（即 canvas）。
  • vec4f 是 vec4<f32> 的简写；array<vec2f, 3> 是定长数组。

💡本例没有任何顶点缓冲区！我们利用 vertex_index 在着色器里查表得到坐标。这是教学常用技巧，下一节才会引入真正的顶点缓冲区。

3) 创建渲染管线

const module = device.createShaderModule({ code: shaderCode });
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex:   { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format }] },
  primitive: { topology: 'triangle-list' },
});

管线把「用哪个着色器、顶点如何排布、输出什么格式、画三角还是画线」等状态一次性打包固化。这正是 WebGPU 高性能的关键——驱动可以提前做好校验和优化，运行时只需切换管线对象。

  • layout:'auto' 让 WebGPU 根据着色器自动推断绑定布局（后面用到 Uniform 时会手动指定）。
  • targets:[{ format }] 必须与 canvas 配置的格式一致。
  • topology:'triangle-list'：每 3 个顶点构成一个三角形。

4) 录制命令并提交

const encoder = device.createCommandEncoder();
const pass = encoder.beginRenderPass({
  colorAttachments: [{
    view: context.getCurrentTexture().createView(),
    clearValue: { r: 0.04, g: 0.04, b: 0.1, a: 1 },
    loadOp: 'clear',   // 通道开始时清屏
    storeOp: 'store',  // 通道结束时保存结果
  }],
});
pass.setPipeline(pipeline);
pass.draw(3);  // 顶点数 = 3
pass.end();
device.queue.submit([encoder.finish()]);

🔁四个核心对象的流水线：

CommandEncoder（命令编码器）→ RenderPass（渲染通道，描述往哪张纹理画、是否清屏）→ encoder.finish() 产出 CommandBuffer → queue.submit() 交给 GPU 执行。

  • getCurrentTexture() 每帧获取 canvas 当前可写的纹理，必须每帧重新获取。
  • loadOp:'clear' + clearValue 等价于 WebGL 的 clearColor + clear。
  • 命令缓冲是一次性的，finish() 后不能再录制；下一帧要重新创建 encoder。

四、常见坑

⚠️必须用本地服务器打开：WebGPU 在 file:// 下通常被禁用。请用 VS Code「Live Server」或 npx serve 启动后访问 http://localhost。

⚠️targets.format 与 configure 的 format 不一致会报管线创建错误。两处都用 getPreferredCanvasFormat() 即可。

⚠️忘记 pass.end() 或 queue.submit()：什么都不会显示，但也不会报错，最易踩。
