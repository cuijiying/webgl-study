15 · 计算着色器 —— GPU 通用并行计算

用 Compute Shader 对图像做卷积，体会 WebGPU 相对 WebGL 的杀手级特性。

一、什么是计算着色器？

前面所有 demo 都走渲染管线：顶点着色器 → 光栅化 → 片元着色器，最终产出像素。但很多计算（图像处理、物理模拟、粒子系统、AI 推理）并不需要画三角形，只是想对大量数据做并行运算。

WebGL 做这类计算非常别扭（要把数据伪装成纹理、用片元着色器变相计算）。WebGPU 直接提供了独立的计算管线和 @compute 着色器，这就是通用 GPU 计算 (GPGPU)。这是 WebGPU 相对 WebGL 最重要的新增能力。

二、并行模型：线程、Workgroup、Dispatch

计算着色器的执行单位是线程 (invocation)。线程被组织成三层：

概念说明
线程 (invocation)最小执行单位，本例中一个线程处理一个像素
Workgroup一组线程，由 @workgroup_size(x,y,z) 定义。本例 8×8=64 个线程
DispatchdispatchWorkgroups(gx,gy,gz) 启动多少个 workgroup

总线程数 = workgroup 数 × 每个 workgroup 的线程数。要覆盖 512×512 的图，每个 workgroup 8×8：

cpass.dispatchWorkgroups(Math.ceil(512 / 8), Math.ceil(512 / 8)); // 64 × 64 个 workgroup
// 总线程 = 64×64 个 workgroup × (8×8) = 512×512，正好每像素一个线程

⚠️由于 ceil 向上取整，边缘的线程可能超出图像范围。所以着色器开头必须越界检查：if (gid.x >= dims.x || gid.y >= dims.y) { return; }

三、global_invocation_id：我是哪个像素？

每个线程通过内建变量 @builtin(global_invocation_id) 知道自己的全局编号，正好对应它要处理的像素坐标：

@compute @workgroup_size(8, 8)
fn main(@builtin(global_invocation_id) gid : vec3u) {
  let dims = textureDimensions(inputTex);
  if (gid.x >= dims.x || gid.y >= dims.y) { return; }
  // gid.xy 就是当前像素坐标
}

四、读写纹理：textureLoad 与 textureStore

计算着色器里读纹理不用 sampler，而是用 textureLoad 按整数坐标精确取像素；写入则用 storage texture + textureStore：

@group(0) @binding(0) var inputTex  : texture_2d<f32>;                          // 只读
@group(0) @binding(1) var outputTex : texture_storage_2d<rgba8unorm, write>;     // 可写

let texel = textureLoad(inputTex, coord, 0).rgb;        // 读 (coord 是整数像素坐标, 0 是 mip 层)
textureStore(outputTex, vec2i(gid.xy), vec4f(color, 1.0)); // 写

对应 JS 端，输出纹理需要声明 STORAGE_BINDING 用途（之后还要被渲染采样，所以再加 TEXTURE_BINDING）：

const outputTex = device.createTexture({
  size: [W, H], format: 'rgba8unorm',
  usage: GPUTextureUsage.STORAGE_BINDING | GPUTextureUsage.TEXTURE_BINDING,
});

五、卷积运算原理

卷积是图像处理的核心操作：用一个 3×3 的卷积核 (kernel) 在图像上滑动，把每个像素及其 8 个邻居按核里的权重加权求和，得到新像素值。

设核为 $K$，结果像素 = $\text{factor} \times \sum_{i} (K_i \times \text{邻居}_i) + \text{bias}$。不同的核产生不同效果：

效果卷积核说明
原图中心 1，其余 0不改变
均值模糊全 1，×1/9取邻域平均
高斯模糊1 2 1 / 2 4 2 / 1 2 1，×1/16加权平均，更自然
锐化中心 5，上下左右 -1增强对比
边缘检测中心 8，周围 -1突出轮廓
浮雕方向梯度，+0.5 偏移立体浮雕感
var sum = vec3f(0.0);
var idx = 0;
for (var dy = -1; dy <= 1; dy++) {
  for (var dx = -1; dx <= 1; dx++) {
    let coord = clamp(vec2i(gid.xy) + vec2i(dx, dy), vec2i(0), vec2i(dims) - vec2i(1));
    sum += textureLoad(inputTex, coord, 0).rgb * k[idx];
    idx++;
  }
}
let outColor = clamp(sum * factor + vec3f(bias), vec3f(0.0), vec3f(1.0));

📐用 clamp 把邻居坐标限制在图像范围内，处理边缘像素时避免越界（相当于「边缘扩展」）。

六、两个通道：先计算，再显示

计算着色器把结果写进了 outputTex，但它是一张纹理、不是画布。要看到结果，还需要一个渲染通道把这张纹理画到屏幕（用全屏三角形采样它）。两个通道放在同一个命令编码器里，按顺序执行：

const encoder = device.createCommandEncoder();

// 通道 1：计算（跑卷积，写 outputTex）
const cpass = encoder.beginComputePass();
cpass.setPipeline(computePipeline);
cpass.setBindGroup(0, computeBindGroup);
cpass.dispatchWorkgroups(Math.ceil(W / 8), Math.ceil(H / 8));
cpass.end();

// 通道 2：渲染（采样 outputTex，画到画布）
const rpass = encoder.beginRenderPass(/* ... */);
rpass.setPipeline(renderPipeline);
rpass.setBindGroup(0, renderBindGroup);
rpass.draw(3);   // 全屏三角形
rpass.end();

device.queue.submit([encoder.finish()]);  // 一次提交，自动处理两通道间的依赖

✨WebGPU 会自动在两个通道之间插入资源同步屏障：保证计算通道写完 outputTex，渲染通道才开始读它。无需手动管理。

七、计算着色器还能做什么？

  • 粒子系统：每个线程更新一个粒子的位置/速度，可达百万级。
  • 物理模拟：布料、流体、N-body 引力。
  • 图像 / 视频处理：滤镜、色彩校正、卷积神经网络。
  • 排序 / 归约：并行前缀和、并行排序。
  • 剔除 / LOD：在 GPU 上做视锥剔除，再间接绘制。

八、动手练习

  1. 加一个 5×5 的高斯核，对比 3×3 的模糊强度。
  2. 实现 Sobel 算子（水平 + 垂直梯度求模）做更好的边缘检测。
  3. 把 @workgroup_size 改成 16×16，观察是否更快（注意上限通常 256 线程）。
  4. 加载真实图片作为输入纹理，做实时滤镜。
  5. 挑战：用计算着色器实现一个简单的粒子系统。
