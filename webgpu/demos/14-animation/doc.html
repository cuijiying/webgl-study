14 · 动画 —— 渲染循环与时间管理

用 requestAnimationFrame 驱动每帧绘制，用 deltaTime 让动画与帧率无关。

一、动画的本质

前面所有 demo 都是「改了参数才重画一次」。动画则是持续地、每一帧都重新绘制，每帧让物体的状态（位置、角度…）改变一点点，人眼看上去就连续运动了。

二、requestAnimationFrame

浏览器提供 requestAnimationFrame(callback)：它在下一次屏幕刷新前调用你的函数。相比 setInterval，它的优势是：

  • 与显示器刷新率同步，画面不撕裂；
  • 标签页切到后台时自动暂停，省电；
  • 回调会收到一个高精度时间戳（毫秒）。
function drawFrame(now) {       // now: 当前时间戳 (ms)
  // ...更新状态、绘制...
  requestAnimationFrame(drawFrame); // 申请下一帧，形成循环
}
requestAnimationFrame(drawFrame);   // 启动

三、关键：deltaTime（帧间隔）

如果直接写 angle += 0.02，那么 144Hz 显示器上物体会转得比 60Hz 快一倍多——因为帧数更多。正确做法是按真实流逝的时间来推进：

let last = 0;
function drawFrame(now) {
  if (!last) last = now;
  const dt = (now - last) / 1000;  // 两帧间隔，换算成「秒」
  last = now;

  angle += speed * dt;  // speed 单位是「弧度/秒」，乘 dt 得到这帧应转的量
  // ...
}

⏱️核心思想：把速度定义为「每秒变化多少」，再乘以 dt。这样无论帧率高低，每秒的总变化量都相同——动画速度与设备无关。

四、暂停 / 恢复的小陷阱

暂停一段时间后恢复，now - last 会变得很大，导致物体「瞬移」。解决办法是恢复时把 last 清零，让下一帧重新校准：

toggleBtn.addEventListener('click', () => {
  running = !running;
  last = 0;   // ← 重置，避免 dt 突然变大造成跳变
});

五、每帧都要更新 GPU 数据

动画里矩阵每帧都在变，所以每帧都要 writeBuffer 把新矩阵上传，再录制并提交命令。本例复用了第 13 节的动态偏移技术，一次性更新所有物体后逐个绘制：

device.queue.writeBuffer(uniformBuffer, 0, big, 0, n * (256 / 4));
const encoder = device.createCommandEncoder();
const pass = encoder.beginRenderPass(/* ... */);
// ...逐物体 setBindGroup + draw...
pass.end();
device.queue.submit([encoder.finish()]);

🔁注意：每一帧都要重新录制命令。command encoder 用完即弃，不能跨帧复用。这正是 WebGPU「命令录制」模型与 WebGL「立即模式」的核心区别。

六、FPS 统计

累加 dt 和帧数，每隔 0.5 秒算一次平均帧率：

fpsAcc += dt; fpsCount++;
if (fpsAcc >= 0.5) {
  fps = Math.round(fpsCount / fpsAcc);
  fpsAcc = 0; fpsCount = 0;
}

七、动手练习

  1. 让每个物体的旋转轴不同（X / Y / Z 交替）。
  2. 加一个「整体绕中心公转」的运动（结合 sin/cos 改物体位置）。
  3. 用 Math.sin(elapsed) 做出物体上下浮动的缓动效果。
  4. 把速度滑块改成可正可负，实现反向旋转。
